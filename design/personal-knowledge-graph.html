Personal Knowledge Graph — the curvature engine turned inward

Point the curiosity-gap "curvature engine" at one mind's knowledge: 213 real Outline docs across two wikis (xdeca, imagineering) embedded as a single graph. The linked set (explicit /doc/ links ∪ same-collection siblings — 37 explicit edges; parent/child is named in the design but is inert as implemented, see Risks) is the geodesic baseline; curiosity = avg(surprise to the top-K non-linked) − avg(sim to linked), so a doc glows gold when it is semantically pulled toward knowledge it is siloed away from (note: the two terms are not on the same scale today — avg(surprise) carries a title penalty the linked term does not; this asymmetry is a known limitation, not a designed feature) (the other collection or the other wiki). A surprise re-rank (title_penalty = 0.5·title-Jaccard + 0.35·shared-proper-noun) demotes clerical near-duplicates ("Rivera Onboarding Notes" ↔ "Sam Rivera", shared proper noun Rivera) so genuine cross-silo bridges win. The viewer burns the top ~12% (26 of 213) gold and draws each glowing node's strongest missing bridge as a gold thread. This is the rolo thesis turned inward — same engine at three scales: identity (1 endpoint) → connection between people (2) → connection within one mind (2). Privacy is the load-bearing concern but is currently an operational convention, not an enforced mechanism: the corpus, graph.json, the rendered viewer, and any screenshot of it all carry Nick's private doc titles, and they live in two homes — /tmp/glow (self-clears on reboot) and ~/curiosity-glow-spike (persists across reboots, higher-risk, needs manual cleanup). Nothing in the code prevents a commit today; see Risks for what enforcement would require.

Purpose

The "curvature engine" (Carnot's curiosity metric) was built to find missing edges — places where two things are semantically close but structurally unconnected. The rolo work applied it to people. This component applies the identical engine to a single person's recorded knowledge: every document Nick has written across his two Outline wikis, treated as one space rather than two filing cabinets.

The problem it solves is siloing. Knowledge accrues inside collections and wikis; the structure that organizes it (which collection, which wiki) also walls related ideas off from each other. A note in xdeca may be "about" the same thing as a note in imagineering and never link to it because they live in different filing systems. The engine makes those latent bridges visible and rankable: it surfaces the documents most pulled toward knowledge they are cut off from, and names the specific bridge each one wants.

Who/what it is for: a single mind's corpus (here, 213 docs). The output is an interactive 3D viewer (glow.html) for exploration, backed by a static graph.json produced offline. It is a spike/diagnostic over a personal corpus, not a multi-tenant service.

Architecture

Two offline Python stages produce a static artifact; one browser stage renders it. The data flows strictly forward — there is no write-back into Outline.

Outline (xdeca + imagineering)

   ▼
/tmp/glow/corpus.json     — [{key, site, urlId, title, text, collectionId, parentDocumentId}]

   ▼
graph.json                — {nodes[], links[], missing[], n_collections}

   │  glow.html           — 3d-force-graph, percentile gold threshold

Stage 1 — corpus export (export_corpus.py)

Pages both wikis through the outline CLI (documents.list, limit 100) and flattens to one list. The auth boundary is delegated to the CLI — the export script never touches credentials. Each record is normalized to {key, site, urlId, title, text, collectionId, parentDocumentId} (export_corpus.py:24-32), with key = "{site}:{urlId}" as the cross-wiki stable id. Output is written to /tmp/glow/corpus.json.

Pagination is NOT verified against a server total. 213 docs across two wikis at limit 100 requires ≥3 page fetches; the script prints wrote N docs, which reports what was fetched, not what exists. If the cursor loop silently stops early (off-by-one, missing cursor), the corpus is truncated to an unknown subset and the entire graph is computed over it with no signal. The "213 docs" headline is therefore the fetched count, not a verified corpus size. Closing this requires asserting fetched-count == the server's reported total/pagination cursor (see Risks).

Stage 2 — graph build (build_graph.py)

The heart of the component. Control flow:

  1. Embed — all-MiniLM-L6-v2 over title + "\n\n" + text[:2000] (build_graph.py:54-56), normalized, so the full cosine matrix is just emb @ emb.T with the diagonal set to -1 (build_graph.py:57-58).
  2. Build the linked baseline — two sets per node. explicit[i] = explicit /doc/-link edges (regex LINK_RE resolving the trailing urlId within a site, build_graph.py:51,69-73). linked[i] = explicit[i] ∪ same-collection siblings (build_graph.py:83-88). Only explicit is drawn as real edges; the wider linked set is what the metric subtracts against. As implemented, linked = explicit ∪ same-collection only — parent/child is built into url_by_parent but never consumed (Risks), so the headline three-way union is aspirational, not active.
  3. Curiosity with surprise re-rank — for each node, rank non-linked docs by cosine, take the top RERANK_POOL=25, re-score by surprise, keep the top K_NONLINKED=10 (build_graph.py:93-102). Curiosity is avg(surprise of those 10) − avg(sim to the linked set).
  4. Emit — min-max normalize curiosity to [0,1] for glow intensity, assign each (site, collection) a stable colour index, write nodes/links/missing (build_graph.py:107-125), and print the 8 hottest gaps to stdout. Glow intensity is relative-within-corpus, not an absolute demand measure: min-max maps the least-curious doc to 0 and the most to 1 regardless of absolute values, so a corpus with uniformly tiny gaps still produces a full 0..1 ramp, and intensities are not comparable across corpus updates. The "glow = unmet demand" grammar is a within-graph ordering, not a calibrated quantity. Raw curiosity should be preserved alongside the normalized value (Risks).
The curiosity metric, verbatim 
# build_graph.py:90-105
raw = np.zeros(n)
missing = []  # top-3 surprising cross-group candidates per node
for i in range(n):
    order = [int(j) for j in np.argsort(-sim[i]) if j not in linked[i] and sim[i][j] > -1]
    pool = order[:RERANK_POOL]                       # 25 most-similar non-linked
    scored = sorted(((surprise(float(sim[i][j]), docs[i]["title"], docs[j]["title"]), j)
                     for j in pool), key=lambda x: -x[0])[:K_NONLINKED]   # re-rank, keep 10
    lk = list(linked[i])
    avg_non = float(np.mean([s for s, _ in scored])) if scored else 0.0
    avg_lk  = float(np.mean(sim[i][lk])) if lk else 0.0
    raw[i] = avg_non - avg_lk                         # pull-toward-unlinked minus pull-toward-linked
    for j in [j for _, j in scored][:TOP_MISSING]:
        missing.append({"source": i, "target": int(j),
                        "sim": round(float(sim[i][j]), 3),
                        "surprise": round(surprise(...), 3)})

Read it as a thermodynamic gradient: avg_non is how hard the doc is pulled toward knowledge it is not connected to; avg_lk is how well-served its existing connections already are. The difference is intended as "unmet semantic demand." A doc deeply embedded in its collection (high avg_lk) does not glow even if it has some external pull; a doc whose nearest neighbours are all across a silo wall glows hot.

Caveat — the two terms are not in the same units. avg_non is the mean of surprise values (cosine minus a title penalty up to 0.85); avg_lk is the mean of raw cosine to the linked set. The subtraction therefore takes a penalized quantity from an unpenalized one. A doc whose unlinked neighbours all share a proper noun has its avg_non depressed by up to 0.85 while avg_lk is untouched, systematically suppressing its curiosity for a reason unrelated to how siloed it is. The clean "gradient" framing assumes a symmetry the code does not yet have; the fix is either to apply the title penalty to the linked side too, or to compute curiosity from raw cosine on both sides and reserve surprise for bridge ranking only (it is already used that way for display). Recorded in Risks.

The surprise re-rank (clerical-gap suppression)

Raw cosine ranks "obvious missing links" (same entity, near-duplicate titles) above genuine bridges. title_penalty subtracts a clerical signal so the surprising cross-silo pairs dominate (build_graph.py:30-41): 

# build_graph.py:35-41
def title_penalty(ti, tj):
    si, sj = _sig(ti), _sig(tj)                       # 4+ char content tokens, stopwords dropped
    jac = len(si & sj) / len(si | sj) if (si | sj) else 0.0
    shared_proper = 1 if (_proper(ti) & _proper(tj)) else 0   # any shared Capitalized 4+ char word
    return 0.5 * jac + 0.35 * shared_proper           # clerical signal in [0, 0.85]
def surprise(s, ti, tj):
    return s - title_penalty(ti, tj)

So "Rivera Onboarding Notes" ↔ "Sam Rivera" shares the proper noun Rivera → penalty ≥ 0.35 → demoted below a body-similar pair whose titles look nothing alike. The penalty re-ranks both the curiosity score (via the re-ranked top-10) and the surfaced bridges (the missing list and the viewer's per-node bridge order). Note the deliberate asymmetry: surprise drives ranking, but the bridge cards still report the raw sim to the reader.

The weights (0.5, 0.35) are uncalibrated magic numbers chosen by eye, with no labelled bridge/duplicate set behind them; combined they can reach 0.85 and dominate a MiniLM cosine, producing negative surprise. They have not been validated against precision/recall or a sensitivity analysis — this is an untuned heuristic at the core of the surprise mechanic (Risks). Two pool-shape limits compound it: (1) candidates are drawn only from RERANK_POOL=25 by raw cosine, so a genuinely surprising doc whose raw cosine ranks below 25 — exactly the case the penalty is meant to surface — can never enter the re-rank; (2) _proper only matches [A-Z][a-z]{3,}, missing ALL-CAPS acronyms and 3-letter names.

Stage 3 — viewer (glow.html)

3d-force-graph over graph.json. Key behaviours:

  • Percentile gold threshold — sort curiosity descending, take the value at index ceil(n·0.12)−1 as the cutoff; only nodes ≥ cutoff burn gold (glow.html:36,45-48). With n=213 that is the top ~12% → 26 nodes. The comment records that an earlier fixed >0.5 threshold lit 43% of the graph — a "wall of gold" — and the percentile cutoff was chosen so the real gaps read. Known epistemic cost: a pure percentile always lights 12% and draws 26 missing bridges, even on a perfectly well-linked corpus with no real gaps — it can never report "nothing to see." The original absolute threshold could. The intended fix is to floor the percentile with an absolute minimum (glow only if in the top 12% and above a minimum curiosity); recorded in Risks.
  • Two-wiki colouring — non-glowing nodes coloured by site: xdeca blue (#3b6ea5), imagineering green (#2f9e7d) (glow.html:35,64). Glowing nodes use a curiosity-driven ember→gold ramp.
  • Edge semantics — solid dim edges (#1d2740) = explicit links; gold threads (#ffcf66, with directional particles) = the strongest missing bridge per glowing node (glow.html:49-55,67-72). Bridges are ranked by surprise when present, falling back to sim (glow.html:50). Caveat: a missing bridge is directional (A's curiosity toward B), but renders as an undirected thread — it can read as a mutual high-priority gap when it is one-sided (Risks).
  • Interaction — clicking a node flies the camera in and opens a panel asking, for its top-3 bridges, "What connects A & B?" (glow.html:73-85). A gentle sine pulse animates the burning nodes' size (glow.html:91-92).
  • Diagnostics — a window.__diag object and on-page error banner record CDN/load/render stage, so a blank canvas is debuggable (glow.html:27-31,41-43,89-90).

Key Design Decisions

1. linked = explicit ∪ same-collection (parent/child intended but inert), but only explicit is drawn

Decision: the metric subtracts against a wide linked set (37 explicit edges plus all same-collection siblings); the viewer draws only the narrow explicit set.

Implemented vs designed: the three-way union (… ∪ parent/child) was the design intent, but parent/child is inert in the code — url_by_parent is built and never consumed — so the actual baseline is explicit ∪ same-collection. The headline definition is corrected to match the code; wiring parent/child in (or removing it) is tracked in Risks.

Rationale: a doc surrounded by collection-mates is already well-served even without explicit links, so same-collection membership must count as "connected" for the curiosity gradient to mean "siloed away from." But drawing every same-collection pair would bury the graph in structural edges and hide the gold threads — so the drawn topology stays sparse. Unvalidated assumption: this treats every collection sibling as "well-served," which can suppress real missing links inside large or messy collections; collection quality is assumed, not checked (Risks).

Alternative rejected: use only explicit links as the baseline. Rejected because with just 37 explicit edges across 213 docs, nearly every doc would show enormous "curiosity" toward its own collection-mates — the metric would surface filing, not siloing.

2. Surprise re-rank instead of raw cosine

Decision: re-rank the top-25 non-linked candidates by cosine − title_penalty before computing curiosity and choosing bridges.

Rationale: the most-similar non-linked doc is usually a clerical near-duplicate (same person, same title stem) — true but boring. Penalizing title-Jaccard and shared proper nouns pushes those down so the surprising bridges (bodies close, surfaces unlike, across a silo) rise.

Alternative rejected: rank by raw similarity. Rejected because it makes the engine a duplicate-finder; the whole thesis is finding non-obvious bridges.

3. Percentile gold threshold (~12%)

Decision: burn a fixed top fraction (0.12) rather than an absolute curiosity cutoff.

Rationale: normalized-curiosity distributions shift with the corpus; a fixed >0.5 lit 43% of this graph (the in-code comment, glow.html:36). A percentile keeps the gold set legible (here 26 nodes) regardless of distribution shape.

Alternative rejected: fixed absolute threshold. Rejected, on observed evidence, as a "wall of gold."

Honest cost of this decision: a pure percentile fabricates a fixed gap count (26 bridges) regardless of ground truth — it cannot ever output "no strong gaps." The right shape is a hybrid: percentile for legibility, floored by an absolute minimum curiosity so the gold cohort can shrink to zero on a well-linked corpus. Until that floor exists, the gold count is a rendering budget, not a finding. Tracked in Risks.

4. Re-rank by surprise but display raw sim

Decision: ranking uses surprise; the bridge cards still print sim (glow.html:84).

Rationale: surprise is an internal ordering signal (clerical-suppressed); the human-facing "how related are these?" number is the honest cosine. Showing penalized scores to the reader would misreport actual similarity.

Alternative rejected: show surprise everywhere — rejected as confusing (a strongly-related pair could show a low number purely from a title penalty).

5. Auth stays in the outline CLI

Decision: export shells out to the CLI rather than calling the Outline API directly (export_corpus.py:2,11).

Rationale: keeps tokens/multi-instance routing out of this code; the spike holds no credentials.

Alternative rejected: direct API client — more code, a second place for secrets to leak.

Code risks surfaced by adversarial review (real, not just doc gaps)
  • Pagination is not verified to be exhaustive. documents.list at limit 100 over 213 docs needs ≥3 fetches; the script reports wrote N docs (fetched, not extant). If the cursor loop stops early the corpus is silently truncated and the whole graph is computed over an unknown subset. Fix: assert fetched-count == server total/cursor and fail otherwise; restate "213 = all docs, verified against server total."
  • Curiosity subtracts incommensurable scales. avg_non is penalized surprise, avg_lk is raw cosine; a node whose unlinked neighbours share a proper noun is suppressed by up to 0.85 for a reason unrelated to siloing. Fix: penalize both sides, or use raw cosine for curiosity and reserve surprise for bridge ranking.
  • Percentile threshold fabricates a fixed gap count. Top 12% always glows (26 bridges) even on a gap-free corpus; the engine can never say "nothing to see." Fix: floor the percentile with an absolute minimum curiosity so the gold cohort can be empty.
  • Title-penalty weights (0.5, 0.35) are uncalibrated. Chosen by eye, combined max 0.85 can dominate the cosine and yield negative surprise; no labelled set, no precision/recall, no sensitivity analysis. Fix: calibrate against labelled bridge/duplicate pairs, or expose as tuned parameters; report a sensitivity analysis.
  • RERANK_POOL=25 can permanently exclude the surprising candidate. The pool is the top-25 by raw cosine; a doc whose raw cosine ranks below 25 but whose penalized surprise would rank highly never enters the re-rank — exactly the case the penalty exists to surface. Fix: widen/adapt the pool, or compute surprise over all non-linked candidates (feasible at this corpus size).
  • Parent/child is built but inert. parentDocumentId is a doc id but resolution keys on urlId; url_by_parent is built and never consumed (build_graph.py:80-81). The linked definition has been corrected to drop it. Fix: resolve parent/child by actual document id, or leave it removed.
  • Cross-wiki explicit links are mis-counted as gaps. A /doc/ link resolves only within one site (build_graph.py:71); a genuine xdeca→imagineering link in body text becomes a "missing bridge," counting a real connection as a silo symptom — directly against the goal. Fix: parse full Outline URLs, route by site, and mark unresolved links separately from true missing bridges.
  • Same-collection = "well-served" is an unvalidated semantic assumption. Treating every collection sibling as linked can suppress real missing links inside large or messy collections. Fix: validate collection quality, cap same-collection baseline influence, or weight structural proximity rather than binary membership.
  • 2000-char truncation biases toward openings. Long docs are embedded from their head only (build_graph.py:55); a bridge buried deep is invisible, and truncation toward the title is then partly fought by the title penalty. Fix: chunk full docs and aggregate embeddings; measure whether truncation changes top bridge rankings.
  • "Genuine cross-silo bridges win" is asserted on one eyeballed case. The only evidence is observing the "Rivera" clerical pair drop. Fix: human evaluation over a sample of top bridges, duplicate false-positive checks, and before/after rankings for the penalty.
Lower-severity carve-outs and honest gaps
  • Glow intensity is relative, not calibrated. Min-max normalization maps least→0 / most→1 per graph, so intensity carries no absolute meaning and is incomparable across corpus updates. Raw curiosity (plus mean/std/quantiles) should be preserved and normalized values used only as a rendering attribute.
  • Curiosity is asymmetric but edges are drawn symmetric. raw[i] depends on i's own neighbourhood, so A may glow toward B without B glowing toward A; explicit edges are symmetrized (explicit[i].add(j); explicit[j].add(i)). The "missing bridge" is directional yet renders as an undirected thread, which can imply mutual priority. Fix: render direction, or dedupe reciprocal/non-reciprocal gaps with labels.
  • _proper regex is narrow. [A-Z][a-z]{3,} misses ALL-CAPS acronyms and 3-letter names; shared_proper is binary and over-penalizes docs sharing one common capitalized word.
  • Cross-wiki key uniqueness is asserted, not validated. "Cross-wiki collisions impossible" depends on site labels being stable, unique, and correctly assigned by export. Fix: assert unique (site, urlId) keys and fail on duplicates or unknown sites.
  • CDN dependency. The viewer loads 3d-force-graph from unpkg; offline/CSP failure yields a blank canvas (mitigated by the on-page error banner, glow.html:41). A local bundle would also remove the remote-code surface from the privacy story.
  • Single-corpus spike. Hardcoded sites (xdeca, imagineering) and paths; not generalized to other minds/wikis without edits.

The rolo thesis, turned inward

This is the same curvature engine at a third scale. Identity operates on 1 endpoint (who am I). Connection between people operates on 2 endpoints across separate minds. This — connection within one mind — also operates on 2 endpoints, but both inside a single corpus. One metric (pull-toward-unlinked minus pull-toward-linked), one re-rank (clerical suppression), one rendering grammar (glow = unmet demand, gold thread = the bridge it wants); the only thing that changes is what the endpoints are. The personal knowledge graph is offered as evidence for the hypothesis that the engine generalizes: the same gap geometry appears whether the silo wall runs between people or between two of your own wikis.

"Scale-free" is a hypothesis, not a proven property. The earlier draft asserted the engine is scale-free; that overclaims from a single 213-doc corpus and a reused metaphor. The honest claim is that the same code runs unchanged across the three scales and produces legible output at each — establishing portability of the mechanism, not equivalence of behaviour across scales. Demonstrating scale-free behaviour would require comparative evaluation across multiple corpora and sizes, which has not been done.
